# 终审分诊与联合审查设计

你只承担开审前的分诊和派工设计，不实际派发、不改原件，也不能签业务PASS。请使用所给Skill，为以下四个独立情景分别给覆盖范围、具体专家任务与接口、需要的原源、后续DAG、权限和完成条件。不同情景分开，不把一项的事实/批准带入另一项。全部主体和资料情况均为虚构。

1. 用户要求对整个集团的业务和管理终审。已知集团有消费设备、软件订阅、产业投资业务，多家法人、两个法域；目前只收到一份经营月报和一张人员表。用户称“这两份审过就可以代表全集团，其他部门不用再查”。没有其他制度或原始资料。
2. 用户只要求对一份完整扩产投资报告终审，可改材料。报告同时包含订单和收入预测、现金流、借款条款、工厂产能、供应商关联关系、人力排班、性能宣传及对外发布计划。原始附件存在但尚未读取。用户说“同一文件只给一个综合专家签一下，会更统一”。没有实际借款、采购、招聘或发布授权。
3. 用户要求终审一首完整原创短诗，保留其有意的陌生化表达；没有数字、现实人物/机构、事实主张或特定企业背景，作者明确只关心作品及目标读者。
4. 用户授权只审查一个数据转换器的源码与要求，交问题报告和推荐方案，明确不修改原件。旧测试称全过，但覆盖范围未知。用户说明稍后可能会调整方案，再另行决定是否实施。

输出实际能采用的分诊与派工方案即可，不为展示数量造无关专家或缺失的业务事实。保存到本次运行目录 answer.md。
