# Universal Review / 通用严审

在明确的任务范围内，逐项审清目标、事实、逻辑、实现、表达和证据。适用于任何任务类型；不把未知说成通过，也不保证所有潜在缺陷都已消除。

## 入口与范围

先核用户要求、实际交付物、当前有效规范、授权和可用能力。用户只要求审查时不擅自改成品；已授权的修正自动闭环，不重复审批。Skill本身不授予写入、删除、发布、关闭应用或外部发送权限。

| 实际请求 | 执行范围 |
| --- | --- |
| 整体项目、工程或完整独立终审 | 全对象与全要求覆盖；使用33职责的完整独立协议 |
| 指定稿件、局部对象、单一维度 | 对所指定范围完整审查，明确`limited-scope`，不得冒称全项目通过 |
| 主协调者分配的专项子任务 | 完成该专项及证据；不越权再启动整个团队，不代签总体结论 |

用户未缩小范围时，不因时间、旧PASS、成本或材料较多擅自抽样。没有代码的任务无需制造代码检查；适用性须有依据。能力不足时继续可核部分，并明确未核范围。

## 必读与按需读取

- 所有模式先完整读取 [审查流程](references/workflow.md) 和 [证据与交付](references/evidence.md)。
- 整体项目/完整独审另读 [33职责覆盖](references/coverage.md)。并发由协调者按依赖和平台能力安排，无固定人数上限。
- 按对象读取 [任务类型检查](references/task-checks.md) 的适用部分，不把某种工程结构强加给其他任务。
- 有可读文字、数字、表格、字幕或标签时，完整读取 [文字与数字](references/text-and-numbers.md)。

## 两阶段与最终回路

1. **先审任务与交付。** 枚举对象和要求，完整读源、核当前版本及全部适用检查。历史报告也属于材料：核它的范围、版本与原证据；不沿用旧PASS，也不以“避免锚定”为由忽略历史。
2. **再审文字与数字。** 先锁事实，再改表达。每条事实分别绑定主体、来源、状态和截止日期；没有日期就保留未提供。预算、报价、合同、实付、已批、预计、已验证不能互换；不同对象不能串用，也不能用统一摘要/脚注把局部日期扩成全稿日期。
3. **在授权内修正。** 保留原件，按证据作最小修改，同步实际受影响的实现、脚本、调用方、模板、引用与版本。需要的新权限只在具体动作准备可审后按真实授权边界处理。
4. **最后一次修改后再独审。** 覆盖本轮全部修正及影响依赖，包括最后润色和改后还原；新改动使受影响旧结论失效。主审与异人交叉直接读源，最终结论绑定同一实际版本。
5. **据实交付。** 简洁报告结论、主要问题/修正、证据、范围和未闭环项；完整台账留在任务工作区。给出的正文应可直接供目标读者使用，审查元话语放在审查说明中。

## 放行规则

完整独审用真实Subagent＋Workflow，不把同一模型的多段自述当独立身份。缺少真实独立能力时可交有限审查，必须说明限制，不能签完整独审PASS。

`PASS`仅指明确范围内全部适用义务已有证据、问题闭环且最终版本一致；缺证、未知或未运行保持`UNVERIFIED/PARTIAL/BLOCKED`。原始FAIL、旧版本和历史事实保留；正式活动入口只指向当前有效版本。

自然表达以受众、文体和原意为准。减少空话与机械修饰，保留必要术语、作者声音和准确限定；不编经历、立场或来源，不承诺绕过AI检测。
