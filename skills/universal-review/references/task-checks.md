# 按实际对象选择检查

这些分支补充通用流程，不限于列出的行业。遇到未列任务，从其目标、有效要求、输入、过程、输出、失败条件和证据逐项建表，不因缺少同名分支而降低深度。

## 工程、软件、知识库与自动化

- 核真实结构/职责、接口、依赖身份集合、入口、配置、数据schema、规则owner与限定委托，不能只数文件或依赖条数。
- 追踪当前实际执行的调用链及全部有关分支：正常、边界、异常、降级、迁移和生成输出。旧实现虽未改但仍被引用，也要纳入。
- 逐脚本将最新有效规范映射到实际行为，记录需改/无需改/历史对象/缺证待核及依据；同步相关调用方、测试、模板、生成结果、登记与文档。
- 正式、辅助、历史、第三方、配置驱动与无扩展名入口分别分类。不把辅助工作区硬当正式数据，不把所有语言强制改写成某一种语言。
- 校验真实CLI/服务/库入口，而不只校验一个未被调用的函数。模板字符串正确不代替真实渲染/生成结果正确。
- 运行适用的行为、边界、异常、集成和回归检查，保留实际输入/源码/工具版本与完整输出。覆盖的对象身份、规则、豁免、skip与待遇前后对应，数量相同不足以证明无遗漏。
- 有效规范未变时不得为绿灯改阈值或削弱断言；有效变更确已发生时，以该来源为依据同步现行代码/测试，旧版本和旧结果封存。
- 修改前后核完整实际对象：普通文件、二进制/附件、目录、新建/删除/更名、运行时配置和派生对象；排除规则有依据，不静默漏掉隐藏或外部依赖。
- 工具/运行时状态/恢复方法采用当前平台真正能力，不强制Git、某操作系统、三层架构或特定数据库；项目已有这些约束时完整遵守。

## 报告、研究、分析与数据

- 核问题定义、样本/对象、时间口径、来源层级、引用原文、反例、因果强度、推导过程和结论适用范围。
- 同源转载不能冒充多个独立证据。缺原始数据、来源冲突或时效不足时明确缺口，不补造引用或平均化矛盾。
- 对数字、公式、汇总、分母、单位、舍入、表格/图表/正文一致性作实际复算；“看起来合理”不算验证。
- 事实、计算、解释、假设、预测、建议和已决定事项分开。关联不写成因果，小样本自评不写成已验证普遍效果。
- 用户授权且确需核实时使用可用的权威原始来源；无法访问的材料不得声称已经读过。专业/高影响结论遵守相应实证标准，不把通用Skill当专业资质。

## 计划、活动、流程、决策与操作

- 核目标和约束是否能同时成立，关键依赖/顺序、责任、时限、资源、容量、预算、风险和验收是否闭合。
- 检查每条分支、异常、交接和恢复，区分最早/最晚、必要/充分、可选/强制；报价不等于预订，申请不等于批准，计划不等于执行。
- 替代方案必须有真实前提，不凭空承诺供应商、资源或价格。建议可以提出待核选项，但不能将其写成已落实事实。
- 实际操作按当次授权执行，核对目标、时点、可逆性和完成回执；不要把审查请求变成付款、发送、预订或发布授权。

## 设计、界面、图像、音视频与其他媒介

- 依据任务brief核受众、信息层级、可读性/可访问性、布局、品牌/风格、内容一致性和交付规格。
- 有可用渲染/预览能力时查看实际输出，检查裁切、溢出、字体、对齐、对比度、字幕/音画时序与尺寸格式；不只读源代码或元数据。
- 文字、图表、字幕和数字照样进入保真核对。图像、音频、文件无法打开时明确未视觉/听觉验证，不凭文件名或“生成成功”签通过。
- 视觉判断与可机械验证条件分开记录，保留任务有意的创作风格，不把个人审美当通用错误。

## 短文本、翻译、答复与单一问题

- 对明确范围完整核原意、事实、语法、数字、术语、引用和受众适配。翻译同时核增译/漏译、语气、限定和格式字面量。
- 没有代码或需要修改的运行环境，就不制造工程对象、程序关闭或新规范层。
- 只审一项就准确报告该项；不能因为内容短就把事实缺口当通过，也不能把专项任务机械扩为全项目审计。
