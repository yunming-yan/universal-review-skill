# 通用覆盖本体：从对象产生职责

本表用于发现审查问题，**不是固定人数清单**。每个完整成品和完整项目都先分诊各维度：适用则拆为可核任务，不适用则给依据；缺能力、缺材料、时间不足属于未核，不是N/A。只有用户明确指定单维度时，才按专项范围交付。

| 维度 | 要回答的具体问题 | 典型直接证据 |
| --- | --- | --- |
| 目标与要求 | 产物支持什么用途？当前约束、验收与实际授权是什么？ | 原任务、有效制度、需求、审批/权限原件 |
| 对象与依赖 | 章节/行项/附件/隐藏内容/入口是否盘全？谁消费结果？正式成品和本任务过程物是否各在正确位置？ | 文件/对象清单、表结构、引用、调用链、适用工作区规则、正式/过程路径及发布写集 |
| 来源与事实 | 主体、时间、范围、状态、引用是否被真实原源支持？ | 原件、来源版本、准确位置、相反证据 |
| 逻辑与判断 | 因果、条件、推论、取舍是否成立？最强反例是什么？ | 事实到结论链、替代解释、假设及重开条件 |
| 数字与模型 | 原值是否抄准？可算项是否实算？口径、精度、数据集合与显示是否一致？ | 数值账本、原数据、真实计算及独立第二路径 |
| 专业与规则 | 所涉法域/时期/行业/科学/技术方法是否适用？ | 当前权威原文、标准、真实方法/测试与专业限制 |
| 人、治理与后果 | 谁受影响、谁有权、谁承担责任？公平、冲突、保密与可逆性如何？ | 授权、受影响方、资源、风险和决策记录 |
| 执行与可用性 | 正常/异常/边界/交接/退出是否可行？目标读者能否使用？ | 行动表、资源/依赖、实际操作、渲染或使用检验 |
| 表达与传播 | 错字、措辞强度、文种、受众及截取误读是否改变事实？ | 原话与逐句对照、格式要求、真实输出 |
| 变更与恢复 | 每一修改有无必要、保护、精确差异、同步与可恢复性？数据迁移和过程物清理的边界为何？ | 原件、方案、全部操作事件、迁移/恢复演练、过程物留存清单及回归 |
| 版本与权威 | 当前入口和规则是否唯一有效？历史、外部变更和本轮是否分开？ | 生效依据、版本链、消费者及同版manifest |
| 证据与终态 | 主审/异人/整件总审是否真实完成？所有问题如何处置？ | 原始回执、独立报告、完整修正复审及最终状态 |

## 双向覆盖矩阵

每行至少包含：

`要求/对象/风险ID｜准确位置和输入版本｜适用依据｜主审任务/真实ID｜终版非作者/真实ID｜重大或跨专业的另行异人原源反证/真实ID（低风险合并写依据）｜直接原源与验证｜发现/修正ID｜最终版本与结论`

从原任务逐条查到产物；再从产物逐章、逐字段、逐行项及所有实际入口反查要求和原源。标题、摘要、脚注、图表、附件、导出、隐藏表/行列、未修改但受影响的依赖都纳入。对数值先程序化枚举再人工分类，单纯搜索数字或计数不能证明语义覆盖。

每个实际目标、要求和重大风险必须有人具体接收。复杂长对象按章节、数据源、期间、法域、方法或消费者细拆，保留不重不漏的交界。不同领域有不同方法时分开派工；少数综合报告不能代替专业覆盖。

## 专案和未知场景

公司/集团级终审先执行 [公司覆盖方法](company-coverage.md)：从实际业务和管理职责发现应审对象，不能只围绕初读已经看到的风险派工。职责—原件—owner—独立审查—跨部门接口均有映射；未知业务/法域继续拆专业任务，资料不足保留未覆盖，不猜全公司完整性。

本Skill不为所有项目预设相同方向或人数。已有有效专案协议明确要求的角色、独立性和验收，作为该任务附加条件映射进矩阵；不能拿本表删掉专案义务，也不能把专案固定数字推广到其他任务。

软件项目使用其实际架构；管理方案使用真实组织制度；科研按其研究方法；创作按brief与受众。没有某类对象就不造代码、董事会、法条或财务报表。未列场景从目标、输入、过程/方法、输出、受影响者、失败后果和证据建立新的专业任务，不因没有同名专家而浅审。

## 最后反查

全部修正后从最终对象重新查矩阵：有无未分配断言、不可访问源、未解释差额、旧版签认、无主依赖、未经授权动作或尚未核的最后润色。完整修正集合覆盖所有操作，含改后还原，不能只看最终diff掩掉过程事件。

签认绑定确切范围和同一最终版本。基线、历史失败和外部变化保留，各自按原版本解释；不把“当前已修”写成“从未出错”。完整新一轮独审重新覆盖当前全范围，旧报告只提供线索。
