# 从风险编排真实专家团

## 数量与独立性

先盘点对象与风险，再派专家。**尽可能细分实际触发且有不同核验问题的职责**：来源、定义、计算、适用解释、反例、期间、附件、使用者和终版表现均可拆开。复杂或高影响领域继续增派；不先定“几个足够”，也不把固定角色表全塞给任何任务。

每个适用问题都有具名责任、直接证据及最终非作者复核。重大/跨专业风险另安排专业主审与不同真实身份的交叉者，双方直接读取所需原源。最后由未兼任所审修改作者的总审完整复查成品。低风险相邻问题可由一位专家合并初审，但逐项记录证据、合并理由和终版非作者复核者；不能把金融、法律、管理和传播等不同高风险领域交给一个综合角色代签。

这里的专家是审查职责，不是人类执照或正式机构身份。记录实际子代理ID、所用模型/能力的已知事实及未确认项。协调者自扮多个角色、同一作者重开自己的报告、几个模型重复摘要、不同名字共用同一计算都不构成独立复核。

## 同一成品的多专业联合审查

一份文件可以同时触发多个专家；派工单位是具体断言、表格、条款、流程或承诺，不是“一文件只给一人”。同版文件可由不同专业并行只读，各自核其原件与方法；交界处设置联合问题ID，明确主责和交叉，避免大家都以为另一个人已查。

建立接口表：`共同指标/主张｜各专业解释与来源｜期间/状态/条件｜下游影响｜冲突/裁定｜最终值与版本｜复核者`。例如产能上限影响收入预测，收入影响回款和偿债，招聘/排班影响成本与交付，法律条件影响现金时点和对外承诺。不能让各段分别正确、组合却不可执行。

专业意见冲突按证据、有效要求和适用条件解决，不投票或折中平均。无法证实时限制相应结论；需要业务选择时写清推荐与权限，不擅替有权人决定。一个writer整合全部修改，非作者再审整件成品，核跨专业数字、条件、状态和版本一致。数量不限于示例，按真实接口继续增派；示例也不是每份文件必须开齐的名单。

## 派工合同与DAG

任务单包含：任务ID、具体风险问题、原源/实物路径或远端ID和准确版本、需完整读的范围、允许写入位置、明确不做的副作用、依赖、完成条件、报告位置及未覆盖项。不把大段聊天替代原文；来源未读或输出截断须补齐并记录。

实际顺序：

1. 盘点/合同与覆盖草表 → 冻结输入、原源和任务单。
2. 专业主审独立取证 → 冻结各自发现和真实计算/检验输出。
3. 不同身份直接回源反证 → 冲突沿证据裁定；必要时增派更具体的方法。
4. 形成审查报告与闭环方案 → 非作者审重大方案；向用户呈现，在已有授权内连续实施。
5. 真实验证 → 相关专业异人核最终版 → 整件非作者总审完整修改并集与依赖。

交叉者可以在不受首审结论引导的情况下先独立检查原源，再比较报告；不能为“盲审”隐去原源、当前版本、已知危险或必要变更理由。数值第二路统一按Q4：派生值独立抽取原数据后另实现或反向勾稽，直接原值独立提取核口径；复跑首脚本是复现，不是独立方法。

共享写集只由确定的整合writer处理。审查者不修改自己将签认的正式对象；确需修正时换执行者或重新安排非作者复审。每个报告先保存完整内容和输入版本，再回传结论及证据入口。晚改内容使相关签认失效。

## 调度、扩展与收口

并发在实际平台限制内由协调者按独立性、上下文和服务反馈安排，不固定上限，也不把“越多专家”理解为盲目最大并发。429时保存原响应和未知任务状态，遵守退避；等待/初始化/运行的任务仍占真实槽位。角色总覆盖保留，必要时分波次完成。

正常波次自动接下一波；后台检查点不要求用户“继续”。新问题、冲突、异常、最后改动和新法域/来源会重开受影响任务。修正与审查没有人为轮次上限，但每次追加要说明其新增核验价值。

收口条件：每个适用问题有具名主审、直接证据与终版非作者覆盖，重大/跨专业风险另有异人原源反证，数值第二路满足Q4；冲突处置、最终同版后逆查无未分配问题或可解决缺口。满足后停止重复找人附和；不能因已派很多人、预算/时间或旧PASS就提前收口。

平台无独立身份或工具时，完成有证据部分，列具体未运行职责与结论限制。不能通过伪造角色、报告份数或自述“专家一致”获得最终PASS。
